## コンテキスト

カラーパレットジェネレーターの画面レイアウトを設計する必要がある。ユーザーはパレットの一覧確認、カラースウォッチの視覚的確認、プロパティ編集を同時に行うワークフローが想定され、情報の一覧性と操作性の両立が求められた。

## 検討した選択肢

### 選択肢 A: 3 カラムレイアウト（左: パレット一覧 / 中央: スウォッチ・チャート / 右: プロパティ）

- 概要: デスクトップ向けにパネル 3 分割。左パネルでパレット選択、中央でビジュアル確認、右パネルでパラメータ編集
- デザインガイドライン根拠: Material Design 3 の Canonical Layouts（List-Detail パターン）に準拠
- メリット: 全情報が一画面で見渡せる、パレット切り替えとプロパティ編集が同時に可能、デザインツール（Figma 等）のレイアウトと類似しユーザーに馴染みやすい
- デメリット: 狭い画面では破綻する、3 カラム分の幅が必要（1024px 以上推奨）

### 選択肢 B: タブ切り替え型シングルカラム

- 概要: パレット一覧 / エディタ / プロパティをタブで切り替え
- デザインガイドライン根拠: Material Design 3 の Navigation Tabs パターン
- メリット: 小さい画面でも使える、情報の焦点が明確
- デメリット: パレット一覧とエディタを同時に見られない、操作のコンテキストスイッチが多い

### 選択肢 C: 2 カラム + ドロワー

- 概要: 左にパレット一覧、右にエディタ。プロパティはサイドドロワーで開閉
- デザインガイドライン根拠: Material Design 3 の Navigation Drawer パターン
- メリット: 中間的なアプローチ、プロパティを隠せるため画面を広く使える
- デメリット: ドロワーの開閉操作が追加、プロパティを常時見ながらの編集が不便

## 決定

**選択肢 A: 3 カラムレイアウト** を採用。カラーパレットツールの主要ユースケースはデスクトップでの使用であり、パレット選択→ビジュアル確認→パラメータ調整の一連のフローを画面遷移なしで完結できることを最優先とした。レスポンシブ対応として 1024px 以下では縦積み（シングルカラム）にフォールバックする。

## 影響範囲

- `index.html`: `<main class="app-main">` 内の 3 パネル構造
- `css/styles.css`: `.app-main`（flex レイアウト）、`.panel-left` / `.panel-center` / `.panel-right`、レスポンシブメディアクエリ
- `js/ui.js`: `renderPaletteCards()` / `renderCenterPanel()` / `renderRightPanel()` の 3 関数に分離

## ビジュアル・インタラクション補足

- 左パネル幅: 264px（固定）、右パネル幅: 304px（固定）、中央パネル: 残りの幅（flex: 1）
- パレットカード選択時に `primary-container` 背景 + `primary` ボーダーでハイライト
- 1024px 以下で縦積みにフォールバック、左パネルは max-height: 220px に制限
- 768px / 480px で追加のブレークポイントを設定（スウォッチサイズ縮小等）
