## コンテキスト

アプリケーションの UI 言語を決定する必要がある。主要ユーザーが日本語話者であることが想定されており、ツールとしての使いやすさを最大化するために UI 言語の選定が重要となった。

## 検討した選択肢

### 選択肢 A: 日本語 UI（ハードコード）

- 概要: すべてのラベル、ボタンテキスト、プレースホルダーを日本語で直接記述
- デザインガイドライン根拠: ターゲットユーザーに合わせたローカライズ
- メリット: 即座に理解できる UI、i18n ライブラリ不要、実装がシンプル
- デメリット: 多言語対応には全面的な書き換えが必要

### 選択肢 B: 英語 UI

- 概要: 国際的なユーザーを想定し英語で統一
- デザインガイドライン根拠: グローバルデザインの標準
- メリット: 国際的に使える、技術用語がそのまま使える
- デメリット: 日本語ユーザーにとって敷居がやや高い

### 選択肢 C: i18n 対応（多言語）

- 概要: i18n ライブラリを導入し、日本語・英語等を切り替え可能にする
- デザインガイドライン根拠: アクセシビリティ・国際化のベストプラクティス
- メリット: 将来の多言語対応に備えられる
- デメリット: 初期実装コストが高い、小規模プロジェクトには過剰

## 決定

**選択肢 A: 日本語 UI（ハードコード）** を採用。主要ターゲットが日本語ユーザーであり、アプリ規模が小さいため i18n フレームワークの導入は過剰と判断した。色名の自動命名（`getColorName()`）も日本語（赤、青、緑 等）で出力する。将来の多言語化が必要になった場合は、文字列を定数ファイルに分離するリファクタリングで対応可能。

## 影響範囲

- `index.html`: すべての静的テキスト（ヘッダー、ラベル、ボタン、プレースホルダー）
- `js/ui.js`: 動的に生成される日本語テキスト（「ベース」バッジ、セクションタイトル等）
- `js/color-utils.js`: `getColorName()` の日本語カラー名マッピング（赤、オレンジ、黄、緑、シアン、青、紫、ピンク、ブラック、ホワイト、グレー）
- `js/state.js`: デフォルト値（コレクション名「カラーパレット」、モード名「ライト」「ダーク」等）
- `js/import-export.js`: エラーメッセージの日本語化
- `<html lang="ja">`: ドキュメント言語の宣言

## ビジュアル・インタラクション補足

- フォント: Roboto を全体に使用（日本語グリフは system-ui にフォールバック）
- タイポグラフィスケール: MD3 の Type Scale（title, label, body）を CSS ヘルパークラスとして定義
- 日本語テキストの表示幅を考慮し、入力フィールドやボタンの幅に余裕を持たせている
